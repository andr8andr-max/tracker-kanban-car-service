# Канбан автосервиса — веб-трекер задач

Веб-канбан для автосервиса по ТЗ (`ТЗ_веб_канбан_автосервис.md`): заказ-наряды на доске по 9 этапам, роли и права, чек-листы, согласование работ, таймтрекинг, комментарии, история VIN/госномера, уведомления (внутренние + Telegram), статистика с экспортом, админ-панель и backup.

## Стек

- **Backend**: Python 3.14, Flask, SQLite (`sqlite3`, без ORM)
- **Frontend**: vanilla JS SPA (ES-модули, без сборки), CSS-переменные под брендбук
- **Realtime**: polling (каждые 30 с) для счётчика уведомлений
- **Telegram**: long-polling `getUpdates`

## Быстрый старт

```powershell
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
.\.venv\Scripts\python run.py
```

Открыть **http://127.0.0.1:8000**

При первом запуске база создаётся и заполняется автоматически (схема, права, роли, статусы, типы работ, шаблоны чек-листов, демо-заказы).

### Учётные записи

| Логин | Пароль | Роль | Примечание |
|---|---|---|---|
| `admin` | `admin123` | Администратор | полный доступ |
| `master` | `123456` | Мастер | при первом входе смена пароля |
| `manager` | `123456` | Менеджер | при первом входе смена пароля |
| `mechanic` | `123456` | Механик | при первом входе смена пароля |
| `diag` | `123456` | Диагност | при первом входе смена пароля |

Восстановление пароля работает через Telegram-бота (код в чат); без настроенного бота обратитесь к администратору.

## Структура

```
run.py                 — точка входа (Flask + планировщик: due/overdue, backup, части)
tracker/
  config.py            — пути, настройки по умолчанию
  db.py                — схема SQLite + миграции
  security.py          — сессии, login/permission required, аудит, пароли
  seed.py              — права, роли, статусы, типы работ, демо-данные
  blueprints/          — auth, board, orders, notifications, stats, admin
  services/            — orders, checklist, notify, telegram, timetrack, backup, scheduler
static/
  index.html           — SPA-оболочка (<!-- LOGO --> — placeholders под логотип)
  css/app.css          — дизайн-токены (:root), компоненты, responsive
  js/                  — app (роутер/шелл), api, ui, i18n (RU/EN)
  js/views/            — board, order, notifications, stats, profile, admin
tests/
  smoke_test.py        — сквозной бэкенд-тест (Flask test client)
  ui_smoke.py          — UI-тест в headless-браузере (Playwright)
data/                  — tracker.db, backups/, secret.key (создаются автоматически)
```

## Основные сценарии

- **Доска**: drag & drop между этапами, фильтры (ответственный, тип работ, приоритет, сроки), поиск по госномеру/VIN/клиенту/телефону/номеру, «только мои», архив.
- **Заказ**: 7 вкладок (основное, работы и согласование, чек-лист, время, комментарии, история, VIN), исполнители этапов, паузы, дублирование, архив/удаление/восстановление.
- **VIN/госномер**: конфликт определяется как тот же VIN в другой ветке истории; переход в «Готово» блокируется до подтверждения объединения (или правки VIN).
- **Согласование**: partial/full/rejected, после диагностики подключаются типы работ и шаблоны чек-листов.
- **Готово**: настраиваемые условия (VIN, обязательные пункты чек-листа, ответственный) в `Администрирование → Настройки`.
- **Уведомления**: типы × роли (матрица), клиентские уведомления в Telegram по коду привязки.
- **Статистика**: KPI, динамика, загрузка, среднее время этапов, просроченные, экспорт CSV/XLSX.
- **Администрирование**: пользователи, роли и 28 прав, статусы (цвет/порядок), типы работ, шаблоны чек-листов и карточек, настройки, Telegram, backup/восстановление, журнал аудита, архив и удалённые.

## Настройки и замены под бренд

- Логотип: заменить плейсхолдеры `<!-- LOGO: заменить на логотип компании -->` в `static/index.html`.
- Цвета/скругления: CSS-переменные в `:root` файла `static/css/app.css`.
- Telegram: `Администрирование → Telegram` (токен бота + логин), привязка сотрудников — в профиле, клиентов — кодом из карточки заказа.
- Backup: ежедневно по расписанию (`backup_time`, хранение `backup_keep_days`), ручной backup и восстановление — в `Администрирование → Backup`.
